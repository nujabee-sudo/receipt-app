# 법인카드 영수증 정리 웹앱 — 설계서

- 작성일: 2026-11-13
- 상태: 사용자 검토 대기
- 참고 양식: `2026년 9월 법인카드(#1234) 사용내역서_김철수M.pdf` 3쪽 이후 ("법인카드사용 지출내역서")

## 1. 목적

법인카드 영수증을 폰으로 찍기만 하면 다음 두 가지를 자동으로 만들어 주는 개인용 웹앱(PWA)을 만든다.

1. **월별 사용내역 엑셀 파일 (.xlsx)**
2. **제출용 PDF**: "법인카드사용 지출내역서" 양식. 페이지마다 사용내역 표가 있고, 그 아래 여백에 해당 영수증 사진이 붙는다.

지금 하는 "표 출력 → 영수증 붙이기 → 스캔" 작업을 없애는 것이 성공 기준이다. 만든 PDF는 상신 문서에 그대로 첨부할 수 있어야 한다.

## 2. 범위

### 포함
- iOS와 안드로이드의 모바일 브라우저에서 동작하고, 홈 화면에 설치하는 PWA
- 연속 촬영과 갤러리 다중 선택으로 영수증 등록
- Gemini API(무료 등급)로 영수증 내용 자동 인식
- 사진 자동 자르기와 "스캔 느낌" 보정
- 최근 입력값 자동완성으로 "내용"과 "사용자" 입력
- 문서 생성 2가지 방식: **이번 달 전체** / **아직 문서로 안 만든 것만**
- 엑셀과 PDF를 저장하거나, 폰 공유 메뉴로 보내기
- 백업 내보내기/불러오기

### 제외
- 카드사 승인내역서 첨부와 대조 (재무과에서 따로 받는다)
- 승인취소 영수증 (인식되면 자동으로 제외)
- 서버, 로그인, 여러 기기 간 동기화, 팀 공유 (나중에 추가할 수 있게 구조만 분리해 둔다. 12절 참고)
- 엑셀에서 고친 내용을 앱으로 다시 불러오기

## 3. 사용자와 운영 환경
- 처음에는 사용자 1명이 쓰고, 나중에 팀원에게 공유할 예정이다. 팀원은 각자 자기 폰에 설치하고 자기 Gemini 키를 넣는다.
- 모든 데이터는 사용자 폰의 브라우저 저장소(IndexedDB)에만 있다.
- 비용 목표: 0원. 무료 호스팅과 Gemini 무료 등급을 쓴다.

## 4. 화면과 사용 흐름

### 4.1 홈 (월별 목록)
- 위쪽: 월 선택(◀ 2026-11 ▶), 그달 합계 금액과 건수
- 목록: 날짜별로 묶은 영수증. 각 줄에 썸네일, 금액, 내용이 보인다. 상태 표시는 다음과 같다.
  - ⏳ 인식 중 / 인식 대기
  - ⚠ 확인 필요 (빈 칸이 있거나 검증에 실패한 경우)
  - ✓ 문서 생성 완료
- 접힌 "제외됨" 영역: 승인취소로 판정된 건. 잘못 판정됐으면 복원할 수 있다.
- 아래쪽: **[촬영]**, **[문서 생성]** 버튼

### 4.2 촬영
- 위쪽에 **"현재 현장"** 선택 칸이 있다. 최근 목록에서 고르거나 새로 입력한다. 이후 찍는 영수증의 "현장" 기본값이 된다.
- [촬영]: `<input type="file" accept="image/*" capture="environment">`로 기본 카메라를 연다. 한 장 찍은 뒤 바로 다음 촬영으로 이어진다.
- [갤러리]: 여러 장을 한 번에 선택한다.
- 등록하는 즉시 원본을 저장하고 인식 대기열에 넣는다. 사용자는 기다리지 않는다.

### 4.3 영수증 확인/수정
- 보정된 사진을 보여준다. [자르기 조정]을 누르면 네 모서리를 손으로 옮길 수 있다.
- 입력 칸:
  - 일자, 시각, 금액, 카드번호 뒷자리, 가맹점: 자동으로 채워진다.
  - **현장**: 기본값은 촬영 때의 현재 현장. 자동완성 지원
  - **항목**: Gemini 추천값. 자동완성 지원
  - **사용자**: 여러 명을 칩으로 선택. 기본 사용자가 미리 선택되어 있고, 최근 이름이 후보로 뜬다.
- "내용"은 `{현장} : {항목}`으로 조합한다. 예: `가나테크_서울 본사, 1호기 시운전 : 주유(쏘렌토)`
- [사진 추가]: 한 건에 사진을 여러 장 붙일 수 있다 (긴 영수증, 카드 전표가 따로 있는 경우).
- [확인]: 검증을 통과하면 `done`으로 바꾸고, 확인이 필요한 다음 건으로 이동한다.
- [삭제]

### 4.4 문서 생성
1. 대상을 고른다: **이번 달 전체** / **아직 문서로 안 만든 것만** (현재 선택한 달 기준)
2. 대상에 ⚠ 또는 ⏳ 건이 있으면 목록을 보여주고 "그래도 진행 / 돌아가서 확인" 중에 고르게 한다.
3. PDF 미리보기 화면에서 **[PDF 저장/공유]**, **[엑셀 저장/공유]**를 누른다. 공유는 Web Share API(파일 공유)를 쓰고, 지원하지 않는 환경에서는 다운로드한다.
4. 저장이나 공유에 성공하면 포함된 영수증에 `generatedAt`을 기록한다.

### 4.5 설정
- Gemini API 키 (발급 방법 안내 링크 포함)
- 기본 카드번호 뒷자리 (예: `1234`)
- 기본 사용자 이름
- 기본 차량 이름 (예: `쏘렌토`). 주유/요소수 항목 추천에 쓴다.
- 정렬 순서: 최신순(기본) / 오래된순
- 백업 내보내기 / 불러오기
- 저장 공간 사용량 표시

## 5. 데이터 모델 (IndexedDB)

```ts
type ReceiptStatus = 'queued' | 'recognizing' | 'needs_review' | 'done' | 'excluded';

interface Receipt {
  id: string;
  date: string | null;        // 'YYYY-MM-DD'
  time: string | null;        // 'HH:mm'
  amount: number | null;      // 원, 합계 금액
  cardLast4: string | null;
  merchant: string | null;
  approvalNo: string | null;
  site: string;               // 현장
  item: string;               // 항목
  users: string[];            // 사용자
  photos: Photo[];            // 1장 이상
  status: ReceiptStatus;
  warnings: string[];         // 검증 경고 메시지
  isCancellation: boolean;
  generatedAt: string | null; // ISO, 문서 생성(저장/공유) 시각
  createdAt: string;
  updatedAt: string;
}

interface Photo {
  id: string;
  original: Blob;             // 원본 (긴 변 2400px로 축소한 JPEG)
  processed: Blob | null;     // 보정본 (긴 변 1600px 이하, 흑백 JPEG)
  corners: [Pt, Pt, Pt, Pt] | null; // 원본 기준 모서리 좌표 (좌상, 우상, 우하, 좌하)
}

interface Preset { kind: 'site' | 'item' | 'user'; value: string; useCount: number; lastUsedAt: string; }
interface Settings { geminiKey: string; cardLast4: string; defaultUser: string; vehicle: string; sortOrder: 'desc' | 'asc'; }
```

- 어느 달에 속하는지는 `date`로 정한다. `date`가 없는 건은 등록한 달의 목록에 ⚠로 표시한다.
- 자동완성 정렬: 최근 30일 안에 쓴 값을 먼저 보여주고, 그 안에서는 `useCount` 내림차순으로 정렬한다.
- 시작할 때 `navigator.storage.persist()`를 요청해서 브라우저가 저장소를 함부로 지우지 않게 한다.

## 6. 영수증 인식 (Gemini)

### 6.1 요청
- 모델: Gemini Flash 계열의 무료 등급 모델. 한도에 걸리면(429) Flash-Lite 계열로 한 번 다시 시도한다. **정확한 모델명과 무료 한도는 구현 시점에 Google AI Studio에서 확인한다.**
- 호출 방식: 브라우저에서 공식 SDK(`@google/genai`)로 직접 호출한다. 키는 설정에 저장된 사용자 키를 쓴다.
- 이미지: 긴 변 1600px JPEG(품질 0.85)로 줄여서 보낸다.
- **묶음 요청**: 대기열에 2장 이상이 쌓여 있으면 한 요청에 최대 5장을 보낸다. 각 이미지 앞에 `[#n]` 표시를 붙이고, 결과 배열의 `index`로 짝을 맞춘다.
- 속도 제한: 요청 사이에 최소 7초 간격을 둔다. 하루 한도에 걸리면 해당 건을 `queued`로 두고, 앱을 다시 열거나 다음 날이 되면 다시 시도한다. [다시 인식] 버튼도 둔다.
- 오프라인(`navigator.onLine === false`)이면 대기하고, `online` 이벤트가 오면 재개한다.

### 6.2 응답 스키마 (structured output, `responseSchema`)
```json
{
  "results": [{
    "index": 0,
    "date": "2026-09-29", "time": "18:52",
    "amount": 10000,
    "cardLast4": "1234",
    "merchant": "행복주유소",
    "approvalNo": "12345678",
    "category": "fuel | urea | meal | lodging | parking | toll | pharmacy | convenience | material | other",
    "isCancellation": false,
    "corners": [[x,y],[x,y],[x,y],[x,y]]
  }]
}
```
- `corners`는 이미지 크기 대비 0~1000 정규화 좌표로 받는다.
- 읽을 수 없는 값은 `null`로 받는다.

### 6.3 항목 추천 규칙 (앱에서 처리)
| category | 추천 항목 |
|---|---|
| fuel | `주유({차량})` |
| urea | `요소수({차량})` |
| meal | 시각 < 10:30 → `조식`, 10:30~16:00 → `중식`, 그 외 → `석식` |
| lodging / parking / toll / pharmacy / convenience / material | `숙박` / `주차` / `통행료` / `약품` / `편의점` / `자재 구매` |
| other | 빈칸 (사용자가 입력) |

### 6.4 검증 (하나라도 걸리면 `needs_review`와 경고 문구)
- 필수 값(일자, 금액) 중 빈 칸이 있음
- 일자가 미래이거나, 오늘 기준 3개월보다 이전
- 금액이 0 이하
- `cardLast4`가 설정의 기본 카드와 다름 → "다른 카드 영수증일 수 있어요"
- 같은 일자, 금액, 가맹점의 건이 이미 있음 → "중복일 수 있어요"
- "현장", "항목", "사용자" 중 빈 칸이 있음

모두 통과하고 사용자가 확인 화면을 한 번 열어 [확인]을 누르면 `done`이 된다. `isCancellation`이 true이면 `excluded`가 된다.

## 7. 사진 보정
1. `corners`로 원근 보정 변환(homography)을 계산하고 canvas에서 영수증 영역을 직사각형으로 펴낸다. 8개 미지수의 8×8 연립방정식 풀이를 직접 구현하고, OpenCV.js는 쓰지 않는다(용량이 크다).
2. 흑백 변환 후 레벨을 보정한다. 밝기 히스토그램의 상위 5% 이상은 흰색으로, 하위 2% 이하는 검정으로 맞추고 그 사이는 선형으로 늘린다.
3. 결과는 긴 변 1600px 이하 JPEG(품질 0.8)로 저장한다.
4. `corners`가 없거나 잘못됐으면 사용자가 네 모서리를 직접 끌어서 다시 보정한다. 모서리를 전혀 정하지 않으면 원본 전체에 2단계만 적용한다.

## 8. 문서 생성

### 8.1 PDF 양식
- A4 세로(210×297mm), 여백 좌우 15mm, 위 20mm, 아래 15mm
- 제목: "법인카드사용 지출내역서". 가운데 정렬, 굵게, 약 18pt
- 표: 한 건당 2행, 테두리 실선, 셀 높이 약 9mm, 글자 약 10pt

| 열 비율 | 12% | 22% | 12% | 21% | 12% | 21% |
|---|---|---|---|---|---|---|
| 1행 | 일자 | 2026-09-29 | 카드번호 | 1234 | 사용금액 | 10,000 (우측 정렬) |
| 2행 | 내용 | 가나테크_… : 주유(쏘렌토) (가운데 3칸 병합) | | | 사용자 | 김철수 |

- 표 아래 8mm 띄우고 사진 영역을 둔다. 2열 격자, 열 사이 간격 6mm
- 한글 글꼴(Pretendard Regular/Bold, OFL)을 서브셋으로 PDF에 넣는다 (pdf-lib + @pdf-lib/fontkit). npm `pretendard` 패키지에 고정 굵기 OTF가 들어 있어서 별도 다운로드가 필요 없다.

### 8.2 페이지 배치 알고리즘 (`paginate`, 순수 함수)
입력: 정렬된 영수증 목록(사진의 가로세로 비율 포함). 출력: 페이지 배열(페이지마다 표에 들어갈 건 + 사진 배치 좌표).

1. 영수증을 날짜별 그룹으로 나눈다. 정렬 순서는 설정을 따른다(기본: 날짜와 시각 모두 최신순).
2. 사진 배치: 사진을 순서대로 2열 격자에 넣는다. 한 건의 사진들은 연속으로 놓는다. 각 사진은 열 너비(87mm)에 맞춰 줄이되, 높이가 `남은 사진 영역 높이`를 넘으면 높이에 맞춘다. 한 줄의 높이는 그 줄에서 가장 높은 사진의 높이다.
3. **최소 판독 크기**: 사진의 렌더링 너비가 45mm보다 작아지는 배치는 허용하지 않는다.
4. 탐욕적 채우기:
   - 현재 페이지에 다음 날짜 그룹 전체(표 행 + 사진)가 들어가면 추가한다. → 적은 날이 합쳐진다.
   - 들어가지 않고 현재 페이지가 비어 있지 않으면 새 페이지를 시작한다.
   - 빈 페이지에도 그룹 전체가 들어가지 않으면 건 단위로 나눠서 들어가는 만큼 넣고, 나머지는 다음 페이지로 넘긴다. 한 건의 사진들은 나누지 않는다. 한 건의 사진만으로도 한 페이지를 넘으면 그 건의 사진을 세로로 더 줄여서 넣는다(최소 판독 크기 예외).
5. **페이지마다 완결**: 각 페이지의 표에는 그 페이지에 사진이 있는 건만 들어간다.

### 8.3 엑셀
- 라이브러리: ExcelJS. 시트 이름: `2026-09`
- 열: No / 일자 / 카드번호 / 사용금액 / 내용 / 사용자 / 가맹점 / 승인번호
- 머리글은 굵게, 테두리, 금액은 `#,##0` 형식, 맨 아래에 합계 행, 열 너비 자동 조정
- 정렬은 PDF와 같다. 엑셀은 생성할 때마다 앱 데이터로 새로 만든다.

### 8.4 파일 이름
- 이번 달 전체: `{YYYY}년 {M}월 법인카드(#{카드}) 사용내역서_{기본 사용자}.pdf` / `.xlsx`
- 일부만: 같은 이름 뒤에 `({MM.DD}~{MM.DD})`를 붙인다. 포함된 건의 최소~최대 일자다.

## 9. 백업
- 내보내기: `receipts-backup-YYYYMMDD.zip` (JSZip). `data.json`(영수증, 프리셋, 설정에서 API 키 제외)과 `photos/{id}-original.jpg`, `photos/{id}-processed.jpg`가 들어간다.
- 불러오기: 같은 `id`가 있으면 `updatedAt`이 더 최근인 쪽을 남긴다.
- 마지막 백업 후 30일이 지나면 홈 화면에 백업 권유 배너를 띄운다.

## 10. 오류 처리 요약
| 상황 | 동작 |
|---|---|
| API 키 없음 | 촬영은 되고, 인식은 대기 상태로 둔다. 홈 화면에 "설정에서 키 입력" 배너 |
| 키가 잘못됨 (401/403) | 인식을 멈추고 설정으로 안내 |
| 한도 초과 (429) | Flash-Lite로 1회 재시도 → 그래도 실패하면 `queued`로 두고 나중에 재시도 |
| 네트워크 끊김 | 대기 후 `online` 이벤트에서 재개 |
| 응답 형식 오류 | 1회 재시도 → 실패하면 `needs_review`로 두고 직접 입력 |
| 저장 공간 부족 | 백업 후 오래된 달을 정리하도록 안내 (사진만 지우기 / 전체 지우기) |
| 공유 미지원 브라우저 | 파일 다운로드로 대체 |

## 11. 기술 구성과 모듈 경계
- Vite + React + TypeScript, `vite-plugin-pwa` (오프라인 캐시, 설치)
- Dexie (IndexedDB), pdf-lib + @pdf-lib/fontkit, ExcelJS, JSZip, @google/genai
- 호스팅: GitHub Pages (무료, HTTPS)

| 모듈 | 하는 일 | 인터페이스 | 의존 |
|---|---|---|---|
| `domain/` | 타입, 내용 조합, 항목 추천, 검증 | 순수 함수 | 없음 |
| `storage/` | IndexedDB 읽기/쓰기, 프리셋 갱신 | `receipts.*`, `presets.*`, `settings.*` | Dexie |
| `recognition/` | Gemini 호출, 묶음, 대기열, 재시도 | `recognize(images) → Result[]`, `queue.start()` | @google/genai |
| `imaging/` | 축소, 원근 보정, 스캔 필터 | `warp(img, corners)`, `scanFilter(img)` | canvas |
| `layout/` | 페이지 배치 계산 | `paginate(receipts, pageSpec) → Page[]` | 없음 (순수) |
| `export/` | PDF/엑셀 바이트 생성, 파일 이름 | `buildPdf(pages)`, `buildXlsx(receipts)` | pdf-lib, ExcelJS |
| `backup/` | zip 내보내기/불러오기 | `exportBackup()`, `importBackup(file)` | JSZip, storage |
| `ui/` | 화면 5종 | — | 위 모듈 전부 |

인식 엔진은 `recognition/` 안에서 `Recognizer` 인터페이스 뒤에 둔다. 나중에 Claude API로 바꿀 때는 구현체만 추가하면 된다.

## 12. 나중에 할 일 (이번 범위 아님)

## 13. 테스트
- **단위 테스트 (Vitest)**: `domain`(항목 추천, 검증, 내용 조합), `layout/paginate`(합치기, 나누기, 페이지마다 완결, 최소 크기), `export`(엑셀 셀 값과 서식, 파일 이름), `recognition` 응답 파싱(모의 응답)
- **기준 자료**: 참고 PDF 3~18쪽의 영수증 사진(약 30장)을 잘라 테스트 자료로 쓴다. 정답(일자, 금액, 가맹점)은 표에서 가져온다.
  - 인식 정확도 수동 점검: 무료 한도 안에서 실행. 목표는 일자와 금액 정답률 90% 이상
  - 9월 데이터로 PDF를 생성해 원본과 나란히 놓고 눈으로 비교한다.
- **E2E (Playwright, 모바일 화면 크기)**: 사진 등록 → 확인 → 문서 생성 → 파일 다운로드 흐름. Gemini는 모의 응답으로 대체한다.
- **실기기 확인**: 사용자의 폰에서 홈 화면 설치, 카메라 연속 촬영, 공유 메뉴 동작을 확인한다.
